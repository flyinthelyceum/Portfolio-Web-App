# TASK_AUTHORING_GUIDE.md
Portfolio Web App (Working Portfolio)
Version: v1 (draft)
Authority: CANON.md + LEXICON.md

Tasks are the spine.
If Tasks are vague, the whole app becomes noise.

## 1) Task writing principles

- One Task equals one clear action.
- A Task must earn its place.
- Content can be short. Structure must be clear.
- Every Task should imply what the Log will look like.

Minimum viable Task:
- title that names the action
- one sentence that defines success
- optional resource link or video
- Log Work requirement implied

## 2) Category rules (what each category is for)

### Office Hours
Purpose:
- skill training
- tool certification
- technique demonstrations
- competence checkpoints

Office Hours tasks should be:
- specific
- testable
- repeatable

If certification applies:
- set certificationBadgeId on the Task

Good titles:
- “Illustrator: Offset Path Drill”
- “Tool Cert: Drill Press Safety + Setup”
- “Soldering: Clean Joint Practice”

### News
Purpose:
- announcements
- schedules
- reminders
- links
- admin clarity

News tasks should be:
- brief
- time-bound
- low friction

Logging for News is optional by default.
If you require a log, say so plainly.

Good titles:
- “Studio Schedule Update”
- “Submission Window: Friday”
- “Field Trip Permission Form”

### Project
Purpose:
- long arc prompts
- unit briefs
- constraints and deliverables
- milestone check-ins

Projects should:
- define a constraint
- define a deliverable
- define what counts as progress for Log Work

Good titles:
- “Build v1: Interactive System”
- “Prototype: Nameface Typography”
- “Ten Bullets: Cut and Assemble”

### Chore
Purpose:
- studio operations
- maintenance rituals
- cleanup standards

Chores should be:
- concrete
- checkable
- fast to log

Good titles:
- “Reset Laser Bed”
- “Sweep Zone B”
- “Tool Return Audit”

### Ritual
Purpose:
- recurring practice
- habit loops
- consistent proof

Rituals should:
- be simple
- be sustainable
- generate consistent Logs

Good titles:
- “Daily Documentation”
- “Photo Study: 1 Frame”
- “Iteration Pass”

## 3) Task anatomy (recommended structure)

Task template:

Title:
- verb first if possible

Success:
- one sentence: “Do X. Then Log Work.”

Content:
- short list
- links
- video (optional)

Constraints:
- if needed, include 1–3 constraints max

Expected proof:
- name what a good Log includes (photos, angles, before/after)

## 4) Points posture when authoring

Points are category-based and fixed per category.
You are not changing points per Task in v1.
Instead:
- you shape behavior through category choice
- you shape culture through Features

Use categories intentionally:
- Office Hours and Project are high-value
- News is low-value
- Ritual and Chore create consistency

## 5) Writing style (microcopy)

- Use canonical verbs: Log Work, Publish, Feature, Pin
- Use short sentences
- Use concrete nouns
- Avoid “post” and “assignment”

Preferred tone:
- studio manual
- calm authority
- no motivational fog

## 6) Certification authoring (Office Hours)

To create a certification:
1) Create the badge definition (certification family)
2) Create an Office Hours Task that represents completion
3) Attach certificationBadgeId to that Task

Award rule:
- badge is auto-awarded when a student publishes an eligible Log for that Task

Operational guideline:
- certification tasks should be unambiguous and easy to verify in a Log

## 7) Avoiding dead Tasks

Dead Task symptoms:
- students ask “what do I log?”
- logs are random photos with no pattern
- comments become noise

Fixes:
- rewrite the Task title to name the action
- add one “expected proof” line
- make the Task shorter, not longer
- feature good examples so the pattern becomes visible
