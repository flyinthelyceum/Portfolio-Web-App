# VISIBILITY_MODEL.md

Visibility must be legible and reversible.

## Roles
- Student
- Teacher/Admin
- Public viewer

## Objects
- Task (teacher-authored)
- Log Work (student-authored)
- Comment (student-authored)
- Feature (teacher-authored)
- Highlight (system-curated view)

## Visibility defaults
- Tasks: visible to signed-in students in the class tenant
- Draft Log Work: author + teacher/admin only
- Published Log Work: author + teacher/admin + (optional) class peers + (optional) public
- Comments: visible wherever the target Log Work is visible
- Leaderboard: visible to class tenant; public optional (default off)

## Public/Private toggles
Students can toggle Published Log Work:
- Public
- Private (still published inside class)

Drafts cannot be public.

## Governance
- Teacher/admin can remove comments and revoke visibility of a Log Work.
- Reporting exists for comments (student → teacher/admin).
- Teacher Features are teacher-only actions.
- Highlights are curated and do not require students to “submit to a showcase.”

## Critique posture
- No in-app critique tools (rubrics, grades, critique prompts).
- In-app interaction = likes/comments only.
- Critique happens outside the app.
